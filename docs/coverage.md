# What is modelled, and what is not

The emulator answers reads from a peripheral it does not have with zeros, so firmware that
touches one does not crash; it spins on a ready flag or times out. **The inspector's firmware
panel says which blocks the program touched that are missing**, so it is never a guess.

| WFI/WFE sleep and wake-up (event register, SEVONPEND, SLEEPONEXIT) | done; asleep the core skips straight to its next event, and wakes for SysTick, a timer and a bouncing button's EXTI at the same simulated instants as a spinning core, in-process and in a worker, on the Open746I-C and the Nucleo (`tests/sim/sleep-speed.test.ts`). | Cortex-M7 profile (CPUID, MVFR, cache registers) | done; caches are no-ops |

Every data access and instruction fetch of the core is checked: the highest-numbered region holding the address wins, a disabled sub-region passes it to the region below, the default map is the background for privileged code with PRIVDEFENA, and the PPB and the vector table are always reachable; a refusal is a MemManage with DACCVIOL + MMARVALID and MMFAR (data) or IACCVIOL (fetch), escalated to a forced HardFault when MemManage is disabled or cannot preempt. DMA, DMA2D and the LTDC are bus masters and never checked. The lecturer's `Laba1` (region 0: 4 GB, sub-regions 0x87 off, no access, XN, PRIVDEFENA) runs as before. | Instruction timing | per-instruction cycle counts plus flash wait states: ACR.LATENCY per new 128-bit (F7: 256-bit) line fetched from flash unless the prefetch buffer (sequential code) or the ART / instruction cache (64 lines, LRU) has it; data reads from flash likewise unless the data cache (DCEN, 8 lines) holds the line. **No** bus contention, pipeline or branch-prediction model (M7 dual-issue not modelled). Against the lab's F746 on the bench (2026-10-06, five kernels, caches off and on): cycles per element from 30 % under silicon's (a `udiv` chain; `sqrtf` 9 % under) to 248 % over (`memcpy`; a `volatile` loop +82…+100 %, an integer MAC with the D-cache on +90 %), the M7's L1 caches changing nothing here; a GPIO write takes 1.7–2.2× longer on silicon; so a busy-wait counted in loop iterations runs about 2× long, while SysTick-, timer- and peripheral-clocked timing is not affected (1.1·10⁻⁶ on lab 1's SysTick dwell, 1.8·10⁻⁵ on a PWM period) |
| Debugger, in the code editor (`tests/sim/debug.test.ts`) | done, from the ELF's DWARF (2–5, C and C++). Breakpoints on source lines (gutter or F9), on functions and on addresses, each can be disabled, all saved with the board. Continue/pause (F5), step over/into/out (F10/F11/Shift+F11), by instruction (Alt+F11, or F10/F11 with the disassembly shown), run to cursor (Ctrl+F10), restart. The editor marks the current line and the selected frame's line, shows the frame's locals beside the lines that use them, and gives a value on hover. Panes: locals and globals; watch expressions (C over the program's types: members, indexing, casts, `sizeof`, enumerators, `$pc`/`$r0`/`$s0`, the macros such as `GPIOB->ODR`); the call stack through inlined calls and exception frames; registers; peripheral registers by bit-field (from the CMSIS headers); memory; and disassembly with symbols, branch targets and source lines, for any image (HEX and BIN included). What changed since the previous stop is marked. Values are set in place at a stop, with a row's pencil or a double-click: a variable, a watch, a member or an element to a C expression (C's conversions; a string into a char array), a register of the selected frame (a caller's where its callee saved it), memory in hex. A store to a peripheral register does what that store does; flash and ROM refuse. A value the compiler only computes, or folded into a constant, cannot be set. A fault stops the core as it is entered (on by default), and so does a `BKPT`. A stop freezes the whole bench, and a step advances all of it. Sources come from the board's project, from read-only files added for an image built elsewhere, or from the site (ST's HAL/CMSIS and the build service's startup files). **Not there yet:** watchpoints, conditional breakpoints and hit counts, RTOS thread awareness; a pin changed from the debugger reaches the circuit at the next step |
| Execution speed | decoded instructions are compiled per basic block into JavaScript (`src/mcu/jit.ts`; straight-line code, calls and loops laid out into one function, exceptions and timer events still taken between instructions) — 50–180 MIPS on a desktop, so a 50 MHz F746 runs ~1.5–2× real time and a 200 MHz one at ~0.5–1.7× depending on the code; `pnpm mcu-jit` checks the compiled and interpreted cores agree register-for-register, `pnpm bench` measures every MCU example |

**Supply current** is a datasheet typical per mode, not a model of what the code does: run and
sleep scale with HCLK (all peripherals clocked), Stop by regulator, Standby with the RTC on. A
core sleeping 97 % of the time between SysTicks reads as the blend, and an ammeter on the
board sees the same number.

The MCU side is complete apart from the long tail of blocks no lab has needed (CAN, USB,
Ethernet…); what is still to build is in `plan.md`.

**Digital fast path.** The analog engine steps every 20 µs; a 115200-baud bit is 8.7 µs. Serial
bits therefore travel between an MCU pad and a terminal (or another MCU's pad on the same net, or another pad of the same MCU wired to it: a TX-to-RX or MOSI-to-MISO loopback) as exact-time edges, not as sampled voltages; the analog side still sees the levels for the
scope and the loads. Likewise a PWM faster than the step is sampled at a random instant of each
step, so loads see the true duty instead of an aliased one.

**Digital parts** (the 24Cxx EEPROM, the addressable LEDs) sit on the same exact-time path: each net
with a part, a terminal or a second pad on it is resolved as a wired-AND of its drivers
(open-drain pulls low or releases, push-pull wins, otherwise the pull-ups decide — read off the
analog circuit, so a bus without pull-ups stays low and the firmware times out, as on the bench).
A net that joins only MCU pads goes back to the analog sampler whenever none of them drives it, so
a DAC sweeping a lead into another pad crosses that pad's own thresholds; the pull classification
alone would take an LED on the net (1 kΩ to an anode near 0 V) for a pull-down and pin the level low.
A core with parts on its nets hands over every edge as it makes it, so an EEPROM ACKs at the
clock edge's own time; a part that only listens on a net (a pixel's DIN) takes the edges in order
after the core's run instead, so a WS2812 stream does not stop the core 1.6 million times a second.
Timer outputs carry the time of the compare or update that made them, even when the core catches
the timer up late (after an interrupt's entry, a long block): a PWM edge is never stamped late.

**Series resistors on that path.** A resistor of up to 1 kΩ between two digital pins (an MCU
pad, a part's data pin, a terminal) — the 33–470 Ω series resistor LED datasheets put before DIN,
a current limiter between two boards — joins their nets as well: the level crosses it in
nanoseconds, so the bits stay exact. A resistor to a rail or to an LED keeps the nets apart.

**Switches on that path.** A closed switch, a button held down, a welded contact or anything of 1 Ω
or less (an ammeter) joins the nets on either side into one, as Verilog's `tran` does: a serial
line through a switch arrives as exact-time edges, and opening it splits the net again, each side
keeping its own drivers. A toggle and
every flip of a bouncing contact re-join the nets at the step it happens in. **Not modelled:** a
series resistor above 1 Ω (a 33 Ω termination) still breaks the exact-time path — the line then
travels through the analog solver at its 20 µs step.

**Two cores on one net** (SPI, or anything bit-banged between boards) run in lockstep: the
core that is behind runs until it catches up, yielding whenever it puts an edge on the shared
net, so a slave answers a clock edge at the edge's own time and the master samples the answer
half a period later. Plain GPIO edges on such nets take the exact path too, so a bit-banged
chip select stays in order with the hardware clock. Costs roughly 1.5× over two independent
cores; only cores that share a net pay it.
